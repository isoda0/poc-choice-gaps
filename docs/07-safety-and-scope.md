# 安全性とスコープ境界

## 1. 製品ポジショニング

MVPは「依存症を診断・治療する医療アプリ」ではなく、成人が日常の望まないデジタル習慣を理解し、意図的な選択を増やすためのセルフケア支援です。

製品コピーでは、治療効果、診断能力、医学的な改善を保証しません。

## 2. MVP対象外

- アルコール、薬物など、急な中止に身体的リスクがあり得る対象。
- 自傷・他害など緊急支援が必要な状況。
- 医療的治療を必要とする重度の依存。
- 未成年者向け運用（保護者同意、年齢別安全設計を整えるまで）。
- 医療者の代替としての助言。

上記を将来扱う場合は、対象ごとの独立したSafety Pack、専門家監修、地域別の支援導線、規制・プライバシー評価が必要です。

## 3. Safety Gate

通常推薦より先に実行します。

```text
target supported?
  no → 通常Questを出さず、対象外であることを説明

urgent risk indicated?
  yes → 通常推薦を止め、地域に適した緊急・専門支援を案内

medical withdrawal risk possible?
  yes → 減量・中止Questを出さず、専門家への相談を案内

otherwise
  → 通常の低負担Quest候補へ
```

MVPで対象をYouTubeに固定する場合でも、自由入力やサポート画面から対象外の相談が入る前提でfallbackを設けます。

## 4. LLMの安全境界

- LLMの出力だけでSafety Gateを通過させない。
- 自由入力から危険性が疑われた場合、通常推薦へ自動復帰しない。
- 診断名や治療計画を生成しない。
- 介入はactiveかつ対象に適用可能なテンプレートだけから選ぶ。
- プロンプト・モデル・テンプレートversionを監査可能にする。
- 生成文はschema、長さ、禁止表現を検証する。

## 5. 失敗を責めない設計

介入の実行と対象行動の結果を分けます。

例: 「1分待つ」Questの後にYouTubeを見た場合

```text
Intervention outcome: 1分待てた
Behavior outcome: YouTubeを見た
```

対象行動が発生しただけでQuest全体を失敗とみなしません。ユーザー向けには「できた／少しできた／できなかった」を使い、羞恥や自己否定を強める表現を避けます。

## 6. Privacy by Default

行動・気分・自由入力は機微性が高い前提で扱います。

- PoCは可能な限り端末内保存から始める。
- 収集目的のない自由入力を保持しない。
- 分析イベントと本文データを分ける。
- 削除・リセットを提供する。
- LLMへ送るデータは最小化し、送信内容を説明する。
- 本番前に保存期間、暗号化、ログのマスキング、データエクスポートを決める。

## 7. リリース前レビュー項目

- 行動科学・臨床の専門家レビュー
- 研究エビデンスの一次資料確認
- 医療機器該当性を含む法務・規制確認
- プライバシーポリシーと同意設計
- 危機対応導線の地域別確認
- アクセシビリティと心理的安全性テスト

この文書は安全設計の出発点であり、専門的な安全評価の代替ではありません。
