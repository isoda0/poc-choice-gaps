# UX・初回ヒアリング仕様 v0.1

## 1. 目的

初回ヒアリングの目的はユーザーを完全に理解することではありません。

> 最初の1〜3個の適切なQuestを選べるだけの情報を、最小の負担で取得する。

通常4〜6問、最大7問、目標2分以内とします。必要情報が揃えば途中で終了します。

## 2. Interaction Designの原則

1. **Minimum Necessary Interaction**: 次の意思決定を変えない情報は聞かない。
2. **Progressive Profiling**: 初回で全部を集めず、Day 1〜3の行動から補う。
3. **Prefer Observation over Question**: 将来、端末やQuest結果から分かることは自動取得を優先する。
4. **One Interaction, One Purpose**: 1画面で1つの判断だけを求める。
5. **Conversation is Optional**: ボタンを標準にし、必要なときだけ一言入力、さらに必要な場合だけ会話を使う。

## 3. 最小プロフィール

初回終了時に、次があればDay 1を決められます。

```text
target_behavior
desired_change
main_problem_pattern
main_trigger
motivation
interaction_preference
safety_level
```

`automaticity` や `stoppingControl` などは、回答から推定値とconfidenceを生成します。精度が低くても、候補Questが同じなら追加質問はしません。

## 4. 標準フロー

### Q1. 変えてみたい習慣は？

- UI: single select
- 必須: yes
- 選択肢: YouTube / SNS / スマホ全般 / ゲーム / その他
- MVP: YouTubeのみ利用可能でもよい。他項目は「今後対応予定」と明示する。

保存値: `target.type`

### Q2. 一番変えたいのは？

- UI: single select
- 必須: yes
- 選択肢:
  - なんとなく開くのを減らしたい (`unintentional_open`)
  - 長く見すぎるのを減らしたい (`long_session`)
  - 見る回数を減らしたい (`high_frequency`)
  - 使い方を自分でコントロールしたい (`general_control`)
  - その他 (`other`)

### Q3. 一番近い状態は？

- UI: single select
- 必須: yes
- 選択肢:
  - 気づいたら開いている (`automatic_open`)
  - 見たいと分かっていて我慢しにくい (`urge_control`)
  - 見始めると止めにくい (`stopping_control`)
  - 暇になると他にやることがない (`lack_alternative`)
  - よく分からない (`unknown`)

この回答は初期Intervention Familyを大きく左右します。

### Q4. 特に見てしまうのは？

- UI: multi select
- 必須: no（スキップ可）
- 選択肢: 仕事・学校の後 / 暇 / 疲労 / ストレス / 寝る前 / 決まっていない / その他

保存値: `triggers[]`

### Q5. 今、どのくらい変えてみたい？

- UI: single select
- 必須: yes
- 選択肢: かなり変えたい (`high`) / 少し変えてみたい (`medium`) / まだ分からない (`unknown`)
- 1〜10の数値評価は使わない。

### Q6. 普段の記録はどのくらいなら続けられそう？

- UI: single select
- 必須: yes
- 選択肢:
  - ほぼタップだけ (`low`)
  - 一言くらいならOK (`medium`)
  - AIと話すのもOK (`high`)

### Q7. 条件付き追加質問

次の場合だけ1問追加します。

- `other` を選び、対象や希望を構造化できない。
- `unknown` が複数あり、候補Questが複数Familyに分かれる。
- 安全ゲートに必要な確認が不足している。

入力方法は原則「選択肢 + その他」。自由入力と音声は同じ短文入力の代替とし、音声を必須にしません。

### Optional: 取り戻した時間を何に使いたい？

初回の介入選択には必須ではないため、標準6問の後に任意で聞くか、最初のQuest完了後に段階的に取得します。

- UI: single select + 任意の短文
- 選択肢: 技術学習 / 資格 / 読書 / 運動 / 睡眠・休息 / 家族 / 趣味 / その他 / 今は決めない
- 保存先: `ValueTarget`（BehaviorProfileには埋め込まない）
- スキップしてもDay 1 Questへ進める。
- 企業・大学経由の利用者にも同じ中立な選択肢を出し、スポンサーが事前選択しない。
- 回答はスポンサーへ共有されないことを明示する。

## 5. 質問しない条件

情報不足でも、次のいずれかなら質問せず進みます。

- 回答が変わってもDay 1の選択が変わらない。
- confidenceは低いが、低負担・低リスクな探索Questを出せる。
- 質問予算（最大7問または2分目安）を使い切った。
- ユーザーがスキップを選んだ。
- 後のQuest結果から、より確実に観察できる。
- 現時点の疲労・離脱兆候から、追加質問が継続を損なうと予測される。

質問を止めた理由は内部ログへ `decisionReason` として残します。

## 6. 入力手段の使い分け

| 手段 | 標準用途 | 使わない場面 |
| --- | --- | --- |
| ボタン | 既知のカテゴリ、頻出回答、結果入力 | 選択肢が多すぎる分類 |
| 短文テキスト | 「その他」、視聴目的、任意の補足 | 必須の長文振り返り |
| 音声 | 短文入力の代替 | 静かな場所を前提にする必須操作 |
| AI会話 | 曖昧な回答の構造化、週次振り返り | 初回フロー全体、毎日の必須操作 |

## 7. オンボーディング完了

「分析しています」と長く待たせず、即座にDay 1 Questを提示します。

Welcomeコピー案:

> 自分の習慣を、少しずつコントロールできるように。やめることを強制するアプリではありません。毎日ひとつ、小さな実験を試して、自分に合う方法を見つけていきます。

## 8. Quest実行時のUX

Day 1の例:

> 「何を見る？」を決めてからYouTubeを開いてみよう。見ることを我慢する必要はありません。

視聴目的の入力画面には、必ず `決めずに進む` を用意します。入力をブロック条件にしません。

## 9. Result Check-in

標準質問は1問だけです。

> やってみてどうだった？

- できた (`success`)
- 少しできた (`partial`)
- できなかった (`failed`、内部表現のみ)

### 追加質問ルール

- `success`: 原則終了。
- `partial`: 次Questが変わる可能性がある場合だけ1問。
- `failed`: 情報価値が高いため、負担が許せば理由を1問。

理由の選択肢例:

- Questを忘れていた (`forgot`)
- 面倒だった (`too_burdensome`)
- 見たい気持ちが強かった (`strong_urge`)
- 気づいたら開いていた (`automatic_open`)
- 途中で別の動画へ移った (`continued_browsing`)
- その他 (`other`)

毎回 helpfulness / burden を5段階で聞きません。推薦に必要なタイミングだけ取得します。

## 10. コピーのルール

- UI上で「失敗」と断定しない。
- 診断・治療を想起させる断定を避ける。
- 「してはいけない」より「一度選んでみる」。
- 前日の観察を理由として短く伝える。
- ユーザーが対象行動を行ったこと自体を責めない。
