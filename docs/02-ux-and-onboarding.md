# UX・初回ヒアリング仕様 v0.2

## 1. 目的

初回ヒアリングの目的はユーザーを完全に理解することではありません。

> 最初のPractice Blockを安全に開始できるだけの情報を、最小の負担で取得する。

通常4〜6問、最大7問、目標2分以内とします。必要情報が揃えば途中で終了します。

## 2. Interaction Designの原則

1. **Minimum Necessary Interaction**: 次の意思決定を変えない情報は聞かない。
2. **Progressive Profiling**: 初回で全部を集めず、日々の振り返りから補う。
3. **Prefer Practice over Prediction**: 事前質問で状態を断定せず、低リスクな練習から観察する。
4. **One Interaction, One Purpose**: 1画面で1つの判断だけを求める。
5. **Conversation is Optional**: ボタンを標準にし、必要なときだけ一言入力、さらに必要な場合だけ会話を使う。

## 3. 最小プロフィール

初回終了時に、次があれば最初のPractice Blockを決められます。

```text
target_behavior
desired_change
main_problem_pattern
main_trigger
motivation
interaction_preference
safety_level
```

`automaticity` や `stoppingControl` などは、回答から推定値とconfidenceを生成します。精度が低くても、低負担なAwareness Blockを開始できるなら追加質問はしません。

## 4. 標準フロー

### Q1. 変えてみたい習慣は？

- UI: single select
- 必須: yes
- 選択肢: YouTube / SNS / スマホ全般 / ゲーム / その他
- MVP: YouTubeのみ利用可能でもよい。他項目は「今後対応予定」と明示する。

保存値: `target.type`

### Q2. 一番変えたいのは？

- UI: single select
- 必須: yes
- 選択肢:
  - なんとなく開くのを減らしたい (`unintentional_open`)
  - 長く見すぎるのを減らしたい (`long_session`)
  - 見る回数を減らしたい (`high_frequency`)
  - 使い方を自分でコントロールしたい (`general_control`)
  - その他 (`other`)

### Q3. 一番近い状態は？

- UI: single select
- 必須: yes
- 選択肢:
  - 気づいたら開いている (`automatic_open`)
  - 見たいと分かっていて我慢しにくい (`urge_control`)
  - 見始めると止めにくい (`stopping_control`)
  - 暇になると他にやることがない (`lack_alternative`)
  - よく分からない (`unknown`)

この回答はAwareness Block後の練習順序を決める手がかりにします。回答だけで初日の難易度を上げません。

### Q4. 特に見てしまうのは？

- UI: multi select
- 必須: no（スキップ可）
- 選択肢: 仕事・学校の後 / 暇 / 疲労 / ストレス / 寝る前 / 決まっていない / その他

保存値: `triggers[]`

### Q5. 今、どのくらい変えてみたい？

- UI: single select
- 必須: yes
- 選択肢: かなり変えたい (`high`) / 少し変えてみたい (`medium`) / まだ分からない (`unknown`)
- 1〜10の数値評価は使わない。

### Q6. 普段の記録はどのくらいなら続けられそう？

- UI: single select
- 必須: yes
- 選択肢:
  - ほぼタップだけ (`low`)
  - 一言くらいならOK (`medium`)
  - AIと話すのもOK (`high`)

### Q7. 条件付き追加質問

次の場合だけ1問追加します。

- `other` を選び、対象や希望を構造化できない。
- `unknown` が複数あり、安全な最初のPractice Blockを選べない。
- 安全ゲートに必要な確認が不足している。

入力方法は原則「選択肢 + その他」。自由入力と音声は同じ短文入力の代替とし、音声を必須にしません。

### Optional: 取り戻した時間を何に使いたい？

最初のPractice Blockには必須ではないため、標準6問の後に任意で聞くか、最初のBlock Review後に段階的に取得します。

- UI: single select + 任意の短文
- 選択肢: 技術学習 / 資格 / 読書 / 運動 / 睡眠・休息 / 家族 / 趣味 / その他 / 今は決めない
- 保存先: `ValueTarget`（BehaviorProfileには埋め込まない）
- スキップしても最初のPractice Blockへ進める。
- 企業・大学経由の利用者にも同じ中立な選択肢を出し、スポンサーが事前選択しない。
- 回答はスポンサーへ共有されないことを明示する。

## 5. 質問しない条件

情報不足でも、次のいずれかなら質問せず進みます。

- 回答が変わってもDay 1の選択が変わらない。
- confidenceは低いが、低負担・低リスクなAwareness Questを出せる。
- 質問予算（最大7問または2分目安）を使い切った。
- ユーザーがスキップを選んだ。
- 後のReflectionから、より確実に観察できる。
- 現時点の疲労・離脱兆候から、追加質問が継続を損なうと予測される。

質問を止めた理由は内部ログへ `decisionReason` として残します。

## 6. 入力手段の使い分け

| 手段 | 標準用途 | 使わない場面 |
| --- | --- | --- |
| ボタン | 既知のカテゴリ、頻出回答、定時振り返り | 選択肢が多すぎる分類 |
| 短文テキスト | 「その他」、視聴目的、任意の補足 | 必須の長文振り返り |
| 音声 | 短文入力の代替 | 静かな場所を前提にする必須操作 |
| AI会話 | 曖昧な回答の構造化、週次振り返り | 初回フロー全体、毎日の必須操作 |

## 7. オンボーディング完了

「分析しています」と長く待たせず、最初のPractice Blockと通知時刻の設定を提示します。

Welcomeコピー案:

> 自分の習慣に、少しずつ早く気づけるように。やめることを強制するアプリではありません。毎日ひとつの小さな練習と短い振り返りで、自分で選べる瞬間を増やしていきます。

初期通知時刻は提案しても、本人が変更・スキップできるようにします。通知許可を拒否してもコアデータを失わず、アプリ内で振り返れるようにします。

## 8. Practice BlockとQuestのUX

最初のPractice Blockは、同じAwarenessスキルを最低3回試す仮説で開始します。標準日数は検証後に決めます。

Day 1のQuest例:

> YouTubeを開こうとしていることに気づいたら、心の中で「いまYouTubeを開こうとしている」と言ってみよう。そのまま開いて構いません。開いた後に気づいても練習になります。

Quest画面には次を明示します。

- アプリを先に開く必要はない。
- YouTubeを見てもよい。
- 気づいた時点が遅くても練習になる。
- 日中の入力は不要で、定時に振り返る。

翌日も同じスキルを提示する場合は、目新しいQuestに見せかけません。

> 昨日と同じ「気づく」練習です。繰り返すことで、気づくタイミングの変化を見ていきます。

視聴目的の入力や終了点の設定は、Awareness Blockの後に進むQuestで使います。入力画面には必ずスキップを用意し、YouTube利用をブロックしません。

## 9. Daily Reflection

毎日、本人が設定した時刻にローカル通知を送り、30秒程度で振り返ります。標準フローは次の3問です。

### Q1. 今日、この練習を思い出した？

- 思い出して試した (`practiced`)
- 後から思い出した (`remembered_afterward`)
- 思い出せなかった (`not_remembered`)
- YouTubeを開く場面がなかった (`no_opportunity`)

### Q2. 一番早く気づけたのはいつ？

Q1が `no_opportunity` 以外の場合に表示します。

- 開くより前のきっかけ (`trigger_before_action`)
- 開く直前 (`before_opening`)
- 開こうとしている途中 (`while_opening`)
- 開いた直後 (`after_opening`)
- 見ている途中 (`during_viewing`)
- 見終わった後 (`after_viewing`)
- 気づかなかった (`not_noticed`)
- 思い出せない (`unknown`)

これは優劣の採点ではなく、気づく位置の観察です。後から気づいた場合も否定的なコピーを出しません。

### Q3. 一番印象に残ったきっかけは？

- 仕事・学校の後
- 暇
- 疲労
- ストレス
- 寝る前
- 決まっていない／思い出せない
- その他

毎回、正確な回数、詳細な感情、視聴内容、長文を要求しません。代表的な1場面だけを振り返ります。`helpfulness` と `burden` はBlock Reviewまたは進行判断に必要な場合だけ取得します。

## 10. Block Reviewと進行

最低練習回数を満たした後、次を短く表示します。

- 練習できた回数。
- 観察された最も早いAwareness Timing。
- よく現れたトリガー。
- 次に同じスキルを続けるか、次のスキルへ進む理由。

1日の結果だけではBlockを終了しません。`practiced` と `remembered_afterward` を有効な気づきの練習として数えます。`not_remembered` と `no_opportunity` は練習回数に含めません。忘れた日が多い場合は、スキルを変える前にコピー、通知、合図の負担を調整します。

## 11. 通知の役割

通知の標準用途は、利用直前の割り込みではなく定時のReflectionです。

- 本人が時刻を変更、スヌーズ、停止できる。
- 通知本文に機微な行動詳細を出さない。
- 通知を開けなかった日を失敗扱いしない。
- 翌日に未回答分を強制的に埋めさせない。
- 通知が習慣化を支えるかはMVPで検証する仮説として扱う。

## 12. コピーのルール

- UI上で「失敗」と断定しない。
- 診断・治療を想起させる断定を避ける。
- 「してはいけない」より「気づいたら観察してみる」。
- 「開く前に必ず」ではなく「気づいた時点で」。
- 同じQuestの反復理由を短く説明する。
- 進行理由は1日ではなくBlock内の観察に基づいて伝える。
- ユーザーが対象行動を行ったこと自体を責めない。
