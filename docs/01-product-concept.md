# 構想とプロダクト原則 v0.2

## 1. プロダクト定義

Choice Gap（仮称）は、日常の望まないデジタル習慣に対するセルフケア型の行動変容支援アプリです。

中心に置くのは「対象行動をゼロにすること」ではなく、無意識の行動へ少しずつ早く気づき、自分で選べる能力です。

```text
気づかなかった行動を後から振り返る
  → 行動中に気づく
  → 行動を始めた直後に気づく
  → 行動を始める瞬間に気づく
  → 先行するトリガーに気づく
  → 一度立ち止まり、自分で選ぶ
```

アプリが対象行動の直前に検知・介入することは必須ではありません。平時に1つのスキルを提示し、ユーザー自身が日常で練習し、毎日定時に短く振り返ることで内的なChoice Pointを育てます。

## 2. 解く問題

既存の制限系アプリは、利用時間上限やアプリブロックにより、行動を外側から抑えることに強みがあります。一方で、制限を解除した状況でも自分で選べる能力や、自分固有のトリガーを理解する体験は別の課題です。

本プロダクトは次を解こうとします。

- 気づく前にYouTubeやSNSを開いている。
- 見始めると次の動画へ移り続ける。
- 疲労・退屈・ストレスなど、行動のトリガーを本人が把握できていない。
- その場で止めようとしても、自動的な行動に気づくのが遅い。
- 「また失敗した」という評価が継続意欲を下げる。
- 一般的な助言が、自分の状況や負担に合わない。

## 3. 行動と学習の共通モデル

対象そのものより、行動サイクルと「気づいた位置」をモデル化します。

```text
Trigger → Early Urge → Automatic Movement → Open → Continue → Reward
   ↑           ↑               ↑              ↑        ↑
 early cue   before action    while opening  after    during

                         ↓ scheduled reflection
                 Observation → Learning → Next Practice
```

`Awareness Timing` は固定的な能力ではなく、その日の観察です。MVPでは次の順序で扱います。

```text
not_noticed
  → after_viewing
  → during_viewing
  → after_opening
  → while_opening
  → before_opening
  → trigger_before_action
```

後から気づいた場合も学習の出発点として記録します。早く気づくことを一度の成功条件にせず、複数回の観察で傾向を見ます。

プロダクトの中心機能は `Awareness / Choice / Reflection` です。ユーザーが自動反応から離れて選べる機会を `Choice Point` と呼びます。

## 4. MVPの対象

### 対象ユーザー

- 自分でYouTubeを使いすぎている、無目的に開いていると感じる成人。
- 禁止ではなく、使い方を少しずつコントロールしたい人。
- 1日1つの低負担な練習と、定時の短い振り返りを試せる人。

### 最初の対象行動

`YouTube` の以下2パターンを優先します。

1. `automatic_open`: 気づいたら開いている。
2. `stopping_control`: 見始めると止めにくい。

最初のVertical Sliceは `automatic_open` の気づき練習を中心にします。設計上は他のデジタル習慣へ拡張できるようにしますが、MVPのUI・介入・検証はYouTubeに限定します。

## 5. 価値提案

### ユーザーへの価値

- アプリを先に開くことや、利用を我慢することを要求されない。
- 気づくのが遅かった日も、観察できた日として扱える。
- 同じスキルを繰り返すため、何を練習しているか分かりやすい。
- 自分がどの時点で気づきやすいか、何がトリガーか少しずつ分かる。
- 十分に試してから次の練習が選ばれる。

### 差別化

- ブロックや禁止ではなく、本人の内側にChoice Pointを育てる。
- 利用時間だけでなく「気づくタイミングが早まったか」を評価する。
- 毎日違う助言を出すのではなく、1つのスキルをPractice Blockとして反復する。
- AIの自由生成ではなく、管理された介入カタログと進行ルールから選ぶ。
- 行動結果、スキル実行、気づいたタイミングを分離する。

## 6. 体験の単位

体験の基本単位は、単発の助言ではなく `Practice Block` です。

```text
Practice Block
  ├─ 1つの練習目的
  ├─ 同じInterventionTemplateを使う複数日のQuest
  ├─ 毎日の定時Reflection
  └─ 最低練習回数後のBlock Review
```

Questは次を満たします。

- 1つのスキルだけを練習する。
- 原則10秒以内に思い出して実行できる。
- 日中のアプリ操作を必須にしない。
- 対象行動そのものを禁止しない。
- 気づいたのが行動後でも実行として扱える。
- 何を観察するかが明確である。

最初のQuest例:

> YouTubeを開こうとしていることに気づいたら、心の中で「いまYouTubeを開こうとしている」と言ってみよう。そのまま開いて構いません。開いた後に気づいても練習になります。

## 7. 反復と適応

1日の結果だけで別のQuestへ切り替えません。

- 同じスキルを最低練習回数まで繰り返す。
- `practiced` と `remembered_afterward` を有効な気づきの練習として数える。`not_remembered` と `no_opportunity` は最低練習回数に含めない。
- 忘れた場合は、別スキルへ進まず、同じスキルの合図やコピーを軽くする。
- 負担が高い場合だけ、より低負担な表現へ変更する。
- 気づきのタイミングとトリガーが複数回観察されてから次のBlockを選ぶ。
- 個人化は毎日の目新しさではなく、練習順序・難易度・理由の納得感で提供する。

初期カリキュラムの順序は次を仮説とします。

```text
気づいた時点を観察する
  → 行動をラベリングする
  → 先行トリガーを見つける
  → 一呼吸または短いPauseを入れる
  → 見る目的・終了点を決める
  → 見る／見ない／後にするを選ぶ
  → 自分に合った方法を維持する
```

## 8. 定時の振り返り

MVPでは毎日、本人が設定した時刻にローカル通知を送ります。振り返りは30秒程度、代表的な1場面を中心にします。

標準項目:

1. 今日、Questを思い出せたか。
2. 一番早く気づけたのはどの時点か。
3. 代表的なトリガーは何だったか。
4. 気づいた後に何を選んだか。

定時の振り返りは日中の記憶を完全に再現できるとはみなしません。日中の即時記録は任意で追加できますが、利用直前のアプリ介入や記録をコアループの前提にしません。

## 9. ゲーミフィケーション原則

報酬は禁欲の連続日数だけに付けません。次のプロセスを評価します。

- Questを思い出した。
- 行動後でも自動的だったことに気づいた。
- 以前より少し早く気づいた。
- 一度待てた。
- 目的を決めてから開いた。
- うまくいかなかった理由を振り返った。
- 新しいトリガーを発見した。

複雑なXPやランキングはMVPでは作りません。まず「気づくのが遅くてもゼロに戻らない」言葉と結果設計を検証します。

## 10. 決定済み／仮説／未決定

### 決定済み

- MVPはYouTubeに限定する。
- アプリによる利用直前の検知・介入をコアループの前提にしない。
- 禁止ではなく、気づきとChoice Pointを増やす。
- 1日1Quest、1回30秒程度の定時振り返りを基本にする。
- QuestはPractice Blockの中で複数回反復し、1日の結果だけで切り替えない。
- 推薦はルールベースから始める。
- LLMだけに介入を決めさせない。
- 重度依存や身体的離脱リスクのある対象はMVP外。
- 「減らしたい行動」と「時間を使いたい価値ある活動」を別のTargetとして扱う。
- スポンサーには個人の行動・Quest・ValueTargetを公開しない。

### 検証する仮説

- 初回ヒアリングは通常4〜6問、2分以内なら完了される。
- 日中にアプリを開かなくても、Questを思い出して実行できる。
- 定時の30秒程度の振り返りは継続される。
- 気づきのスキルを反復すると、Awareness Timingが早まる。
- 気づいた後もYouTubeを見てよいコピーが、羞恥を減らし練習継続を支える。
- Block単位の適応が、毎日の変更より習得感と個人化の納得感を生む。

### 未決定

- Practice Blockの最低練習回数と標準日数。
- 通知の初期時刻、再通知、スヌーズの扱い。
- 定時の回想だけで十分か、任意の即時ワンタップ記録を加えるか。
- 正式なプロダクト名。
- SwiftData / Core Data / ファイル保存の選択。
- LLM接続をPoCのどの段階で入れるか。
- 実運用時のアカウント、同期、課金。
