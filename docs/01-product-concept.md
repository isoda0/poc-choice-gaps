# 構想とプロダクト原則

## 1. プロダクト定義

Choice Gap（仮称）は、日常の望まないデジタル習慣に対する行動変容支援アプリです。

中心に置くのは「対象行動をゼロにすること」ではなく、次の能力です。

```text
衝動に気づく
  → 一度立ち止まる
  → 目的や状況を認識する
  → やる／やらないを自分で選ぶ
  → 結果を振り返る
```

外部から行動を禁止するのではなく、無意識の行動を意図的な行動へ変える練習を支援します。

## 2. 解く問題

既存の制限系アプリは、利用時間上限やアプリブロックにより、行動を外側から抑えることに強みがあります。一方で、制限を解除した状況でも自分で選べる能力や、自分固有のトリガーを理解する体験は別の課題です。

本プロダクトは次を解こうとします。

- 気づく前にYouTubeやSNSを開いている。
- 見始めると次の動画へ移り続ける。
- 疲労・退屈・ストレスなど、行動のトリガーを本人が把握できていない。
- 「また失敗した」という評価が継続意欲を下げる。
- 一般的な助言が、自分の状況や負担に合わない。

## 3. 行動の共通モデル

対象そのものより、行動サイクルをモデル化します。

```text
Trigger → Urge → Pause → Choice → Action → Reward → Reflection
                   ^         ^                  ^
                   |         |                  |
                介入点     支援点             学習点
```

プロダクトの中心機能は `Pause / Choice / Reflection` です。ユーザーが立ち止まって選ぶ機会を `Choice Point` と呼びます。

## 4. MVPの対象

### 対象ユーザー

- 自分でYouTubeを使いすぎている、無目的に開いていると感じる成人。
- 禁止ではなく、使い方を少しずつコントロールしたい人。
- 1日1回程度の小さな実験と短い振り返りを試せる人。

### 最初の対象行動

`YouTube` の以下2パターンを優先します。

1. `automatic_open`: 気づいたら開いている。
2. `stopping_control`: 見始めると止めにくい。

設計上は他のデジタル習慣へ拡張できるようにしますが、MVPのUI・介入・検証はYouTubeに限定します。

## 5. 価値提案

### ユーザーへの価値

- 毎日ひとつだけなので試しやすい。
- 行動できなかった日も、情報を得た日として扱える。
- 自分のトリガーと効きやすい介入が少しずつ分かる。
- 前日の結果が翌日の提案へ反映される。

### 差別化

- ブロックや禁止ではなく、Choice Pointの増加を狙う。
- 利用時間だけでなく「意図的に選べたか」を評価する。
- AIの自由生成ではなく、管理された介入カタログから選ぶ。
- 行動結果と介入実行結果を分離する。

## 6. 体験の単位

体験の基本単位は「助言」ではなく「小さな実験（Quest）」です。

Questは次を満たします。

- 1つの目的だけを持つ。
- 原則10秒〜数分で開始できる。
- 対象行動そのものを禁止しない。
- 成功条件が観察可能である。
- 結果から状態モデルを更新できる。

例：

> YouTubeを開く前に、見るものを1つだけ決めてみよう。決められなくても、そのまま開いて構いません。

## 7. ゲーミフィケーション原則

報酬は禁欲の連続日数だけに付けません。次のプロセスを評価します。

- 衝動に気づいた。
- 一度待てた。
- 目的を決めてから開いた。
- うまくいかなかった理由を振り返った。
- 新しいトリガーを発見した。

複雑なXPやランキングはMVPでは作りません。まず「失敗でゼロに戻らない」言葉と結果設計を検証します。

## 8. 決定済み／仮説／未決定

### 決定済み

- MVPはYouTubeに限定する。
- 禁止ではなくChoice Pointを増やす。
- 1日1Questを基本にする。
- 推薦はルールベースから始める。
- LLMだけに介入を決めさせない。
- 重度依存や身体的離脱リスクのある対象はMVP外。

### 検証する仮説

- 初回ヒアリングは通常4〜6問、2分以内なら完了される。
- 10秒程度のQuestは実行される。
- Day 2の適応が個人化の実感を生む。
- 行動を禁止しないコピーが継続率を高める。

### 未決定

- 正式なプロダクト名。
- SwiftData / Core Data / ファイル保存の選択。
- LLM接続をPoCのどの段階で入れるか。
- 通知の時間・頻度。
- 実運用時のアカウント、同期、課金。
